総括文書を `docs/research/20260914-flash-next-initial-analysis-retrospective.md` に作成する。本文だけで経緯・成果・失敗・消費・改善策が理解でき、詳細を調べる場合だけ付録の証跡一覧へ進める構成にする。既存worklogと証拠READMEから案内し、過去の記録は保持する。

## 2. 今回の作業を漏れなく整理する

作業を次のまとまりで説明し、それぞれに「目的、変更、実測結果、残件、次回再利用できるもの」を記載する。

- 既存実装・過去評価の引継ぎと、当初計画・ユーザー判断。
- モデル取得、GGUF検査修正、エンジン変更、GPU・RAM配置、常駐・再起動。
- 原本抽出、全ページ確認、OCR、画像切出し、位置対応、表・注記・期間・単位の結合。
- Compilerと補助計算の修正、原因分析・全社統合で判明した誤り。
- 保存版、再開、BFF・候補画面、新旧版・原ページの確認。
- 品質評価、失敗した方式、未使用評価・通常運用などの未達事項。

実装済み、対象テスト通過、実資料で確認、通常アプリで確認を分ける。6118の「本文確認10/11頁」を数値・分析品質の合格と混同しない。初期の分析試験と、最新の数値採用0・文章未生成も区別する。

付録には試行名、原本、モデル・設定、変更した条件、実要求数、再利用数、時間の意味、結果、保存先を整理する。同じ保存応答や署名版を別の独立試験として重複計上しない。

## 3. 時間・トークン消費の検証と反省

保存ログで確認した、前回回答までの約37時間14分を集計対象として固定する。今回の総括作業は別にする。

現時点の確認値は以下のとおり。

| 記録 | 確認値・扱い |
|---|---|
| 親タスクの推論応答 | 重複のない3,677応答 |
| 入力トークン | 約5億5,348万。その約96.8%がキャッシュ入力 |
| キャッシュ以外の入力 | 約1,770万 |
| 出力トークン | 約318万。推論トークンを重ねて加算しない |
| 文脈圧縮 | 55回 |
| 一時Pythonスクリプト | 証拠フォルダ直下に180本 |
| 確認できた結果ファイル | 直下の各試行に174件。独立したモデル試験174回とは数えない |

応答別使用量の合計が、同じログの最終累計と一致することを確認する。子agentの消費、ローカルモデルのトークン、実行・待機時間は別集計とし、取得できないものは不明とする。ユーザー申告の「プラン消費80%」を、これらのトークン数から料金や消費率へ換算しない。

反省は次を証拠付きで検討する。

- モデルの読取り適性が未確定のまま、基盤・計算・画面の実装を並行して広げた。
- 細かな修正ごとに全資料への再結合、保存、表示確認を繰り返した。
- 大量のツール出力と長い文脈を持ち続け、調査・引継ぎの反復が増えた。
- 仮説、比較条件、打切り判断を先に固定せず、一件ずつ対処を積み重ねた。
- 再利用できる基盤整備と、モデル固有の試行錯誤を十分に分離できなかった。

必要だった作業と削減できた作業を分ける。削減率や次回所要時間は、実測根拠なしに断定しない。

## 4. 読取り失敗の改善案と、次回の進め方

失敗を「実際の誤読・脱落」「画像の解像度や切出し」「文字順・位置対応」「条件の適用範囲」「分析文の意味の誤り」に分ける。

横棒の「一」への誤読については、解像度、前後文、画像の入力処理量、プロンプト、出力形式、エンジン、別OCRで**何が既に失敗したか**を比較表にする。同じ条件の再試行や、有利な応答だけの採用を改善策にしない。

次回の検証手順は以下を提案として文書化する。

1. **保存済みの失敗を整理する。** 再推論なしで、実際にモデルへ渡った画像・設定・生応答・判定を確認する。
2. **少数の難例で適性を見極める。** 横棒・一・1・0、当期と前年、単位、ページ間条件、留保を含む固定集合を用意する。正解は採点側だけが持つ。
3. **一度に一要因を比較する。** 最初の診断予算案は最大2構成・12例、最大24要求とする。追加試験は新しい仮説が得られた場合に別の診断として扱う。
4. **難例を通過してから一社全体へ進む。** その後に調整用・未使用資料、原因分析、通常worker・アプリへ広げる。
5. **モデル交換では差分だけを検証する。** 原本、正解、計算、保存・表示契約を再利用し、変更したモデル・画像処理・接続部分を重点確認する。

診断の投入上限と、決算分析の処理時間上限は区別する。品質を下げたり必要資料を省いたりして時間内に収めない。難例で改善が認められなければ、全工程の修正へ拡大せず、失敗結果と次の選択肢をまとめる。

## 5. 文書の完成条件

- 主要な判断・成功・失敗・未達が、保存証跡へたどれる。
- 消費集計は重複を除き、時間・件数・トークンの単位と対象範囲が明確。
- 画像確認の必須条件と、代替採用案の見送りが明記されている。
- 次の担当者が、既に失敗した試験を繰り返さず、再利用可能な実装から始められる。
- 読み順は「総括本文 → 失敗と改善案 → 試行一覧 → 元ログ」とする。
- 文書とリンクの確認だけを行い、この総括のためにモデル試験・全テスト・ビルドを再実行しない。
