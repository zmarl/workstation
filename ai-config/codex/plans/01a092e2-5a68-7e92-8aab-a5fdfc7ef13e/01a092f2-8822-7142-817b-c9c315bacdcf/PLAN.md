# 既存・新規モデルの保管と利用方法を統一する

## 目的と完了条件

各アプリからダウンロードする場合も、Codexへ取得を依頼する場合も、モデル本体を `D:\Models` 配下へ保存する。既存全モデルを台帳で管理し、導入済み環境で使えるものと、未対応・未検証のものを区別する。

「すべてのモデルをすべてのアプリで実行する」ことは保証しない。モデルごとに対応する利用先を示し、同じファイルの不要な再取得を防ぐ。

## 1. 保存先を最後まで統一する

- GGUF、Hugging Face形式、Ollama形式を同じ保管ルート内で分ける。Hugging Faceのキャッシュ構造やOllamaのblobs/manifestsは保持する。
- LM Studioの共通GGUF設定を維持。Unsloth・Hugging Face系の重み／ダウンロードキャッシュとOllamaのモデル保存先を、ユーザー単位の設定でDドライブへ向ける。認証情報の保存先は変えない。
- Windows、稼働中のWSL、導入済み実行ツールについて、明示パスや環境変数による保存先の上書きを確認する。新しいアプリには同じ確認手順を適用する。
- 既存キャッシュは、利用先と更新中でないことを確認してから移行する。旧パスには互換リンクを残し、今回作った逆向きのリンクとの循環を防ぐ。
- 利用不明のプロセスが存在するだけで全モデルを保留せず、対象ファイルとの関係を調べる。安全を確認できない対象だけ保留し、移行未完了として記録する。
- アプリ同梱モデルはアプリ管理領域に残す例外とする。重複モデルの自動削除・自動変換は行わない。

## 2. アプリ取得とCodex取得を同じ管理へ接続する

共通の管理スクリプトに次の操作を用意する。

| 操作 | 挙動 |
|---|---|
| `sync` | 保存先を走査し、追加・変更・欠損を台帳へ反映 |
| `get` | 取得元・版・形式を照合し、既存ファイルを再利用。必要なファイルだけ共通保存先へ取得 |
| `check` | 実体、付属ファイル、リンク、アプリの参照設定を確認 |

- アプリからの取得は既存のダウンロード機能を使う。完了したGGUFが別アプリのキャッシュにある場合、`sync`でLM Studio用の階層にも複製なしで公開する。
- Codexは取得・利用前に`sync`を実行し、取得には`get`を使う。取得後も台帳を更新する。
- 常駐監視や定期タスクは追加しない。アプリ取得後の台帳更新は、次回のCodex利用時または手動`sync`時に行う。
- ダウンロード途中・分割欠損・取得元不明を正常な取得完了と扱わない。キャッシュ管理下のファイルは、その管理機構を通して取得する。

## 3. 台帳とAI向け案内を整える

- `models.json`を、ファイルから再取得できる情報と、実行検証の記録を分けて更新できる形へ整理する。
- モデルごとに取得元、版、形式、量子化、実体、共通参照先、付属ファイル、対応候補、検証結果を保持する。同じ実体を指すリンクを別モデルとして数えない。
- 再走査で過去の検証記録を消さない。重みや実行環境が変わった場合は、以前の成功を現在の成功と扱わない。
- Codexの共通指示へ「モデル取得・利用時は共通管理文書を読み、台帳を更新する」という短い案内を追加する。詳細は `D:\Models\AGENTS.md` に集約する。
- Claude Code・OpenCode固有の設定変更は今回は含めない。

## 4. 既存全モデルと追加経路を検証する

- 台帳の10モデルに加え、Hugging Face・Ollamaの既存キャッシュも棚卸しする。
- モデルの用途に応じて、導入済み環境で最小の実行確認を行う。文章モデルは短い日本語応答、OCR・画像解析は固定の小さな入力、埋め込みはベクトル生成を確認する。
- GPUを使う検証は一つずつ実施し、今回ロードしたモデルだけを終了する。未対応、メモリ不足、依存不足、認証待ちを分けて記録する。
- 新規取得経路はLM Studio、Unsloth、共通取得コマンドそれぞれで、小容量の公開モデルを使って保存先・検出・台帳反映を確認する。既存モデルの再利用では重みを再取得しないことも確認する。
- リンク循環、同名の別版、途中ファイル、再実行、モデル変更後の検証状態を対象チェックに含める。
- 設定を反映したアプリの通常起動とモデル一覧を確認する。再起動や所有外サービスの停止が必要なら、その対象を未完了として明示する。

## 前提と復元

新しいvLLM等の導入、モデル変換、有料取得、共有サービス設定の変更は行わない。現環境で動かせないモデルは、理由と必要な対応まで提示する。

変更前の設定と移行対応表を保存し、復元は今回変更した項目だけを戻す。完了報告では「保存先の統一」「新規取得経路」「各モデルの動作確認」を分け、残った例外を隠さない。
