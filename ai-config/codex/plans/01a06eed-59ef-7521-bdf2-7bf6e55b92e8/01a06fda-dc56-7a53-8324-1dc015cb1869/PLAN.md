# 財務5項目の実データ接続と照合

## 目的と今回の範囲

売上・売上原価・粗利・販管費・営業利益を、一次資料の出典付きで既存の計算モジュールへ渡せるようにする。実際の決算で計算結果を照合し、入力方法・計算式・不足時の挙動を設計文書へ記録する。

今回確定した方針は以下とする。

- 指定した決算時点までの**公表資料から再計算する方式**を使う。当時アプリが取得済みだった情報の再現とは区別する。
- 保存済み資料を優先し、原本が欠ける場合は、検証対象に必要な資料だけを公式から取得する。
- 共有DBは読み取りのみ。計算結果の本番保存、Qwen・API・画面への接続、収集基盤の修復は今回含めない。

## 実装内容

### 原資料から計算入力を作る

純計算モジュールの外側に、対象文書・企業・基準日時を受け取り、`FinancialPerformanceRequest`と採用根拠・除外理由を返す入力変換処理を追加する。

- 既存DBを文書・保存場所の検索に使い、TDnet／EDINET原本のhash、企業、期間、連結・単体、会計基準、単位、数値位置を確認する。
- 数値は原資料の文字列・桁倍率・符号からDecimalへ変換する。既存の浮動小数の値は照合対象にとどめる。
- 既存の指標対応表と解析処理を再利用し、販管費の名称を計算側の指標名へ明示的に対応付ける。
- 同一資料内の同じ意味・同じ値の重複は、出典をすべて保持して一つの入力にまとめる。異なる値や比較条件の不一致は競合として残す。
- 計算へ採用できることと、DB上の正式な採用状態を変更することを区別する。空の財務数値台帳を埋める処理は追加しない。

### 比較する資料と時点を固定する

- 対象文書を起点に、計算に必要な過去資料を最大8四半期分まで探す。取得できない期間は欠落として返す。
- TDnetとEDINETは別の入力系列として計算・照合する。TDnet開示時点の不足項目へ、後日公表されたEDINET数値を補充しない。
- 公表日時は公式の開示記録から確認する。不明な日時を便宜的に作らない。
- 訂正・再表示は基準日時までの明示的な関係を確認して選択する。関係を解決できない複数候補は、自動的に最新版へ寄せない。
- 通期、累計、単独四半期を区別し、Q4やTTMの材料が不足する場合は計算不能理由を残す。

### 実行結果を確認できる形にする

小さな検証用の実行入口から、次を作業用ファイルへ出力する。

- 対象文書・hash・基準日時・採用した入力と除外理由
- 財務計算の結果、元資料・既存値との照合結果
- 明示した仮定による黒字化条件の計算結果

将来の税・株式数・PERは自動補完しない。入力がなければ営業利益の試算までを残し、一株利益・価格は計算不能とする。

## 検証と受入条件

検証企業は **2796・7602・4587** を基準とし、販管費減少を含む利益改善、赤字縮小、IFRS・累計期間の違いを確認する。企業の選定は検証目的であり、投資評価ではない。

- EDINET原本で5項目の当期・前期を照合し、増減額・利益率・営業利益の増減分解が再現できること。
- TDnetの売上・営業利益から黒字化条件まで実行し、原資料にない粗利等を補っていないこと。
- 丸めによる差を含め、原資料の数値や分解残差を都合よく一致させていないこと。
- 原本欠落、hash不一致、異値重複、期間・連単・単位の違い、基準日時後の訂正を含む反例で、不適切な結果が出ないこと。
- 同じ固定資料と仮定から同じ結果を再現でき、各数値から原資料の位置まで辿れること。
- 対象テストと静的検査を実行する。実資料で未確認の項目は、テスト成功だけで確認済みにしない。

## 文書化と完了状態

既存の財務計算仕様・黒字化評価設計・作業記録へ、入力の採用方法、出典の扱い、照合例、制約、実行結果を追記する。

今回の完了条件は、**実資料から計算入力を作り、3社で利用可能な項目と利用不能な項目を根拠付きで確認できる状態**とする。実装と実データ検証までを対象とし、公開・main統合・アプリ利用開始は別の状態として報告する。
