
# 日々読み返し、考えを深め、更新し続ける投資フレームワークの設計

## 1. 目指す姿と設計方針

投資フレームワークを、**「現在の自分の投資を項目ごとに説明でき、経験や対話によって育て続けられる文書体系」**にする。

本人が読みやすい本文を、人間とAIが共通して参照する。AI専用の別冊に同じ内容を複写せず、明確な項目名、適用範囲、参照リンクによって必要な箇所へ辿れるようにする。

設計の基本は次のとおり。

- 一つの項目で、一つの問いに答える。定義・考え方・例外を近くに置き、その項目だけでも意味が分かるようにする。
- 全体目次から順に読むことも、気になる項目だけ読むこともできる。
- 現在の考え、具体例、未解決の問い、考えが変わった経緯を読み分けられる。
- 本人の明確な意思は出所と理由を残して反映する。迷い・独り言・AIによる新しい解釈は、問いや提案として扱う。
- 更新回数や取引件数を、考えの言語化・訂正の条件にしない。投資効果の検証が必要な場合は、その目的と方法を別に扱う。

今回の実行対象は、文書体系と関連設計の整備まで。アプリへの接続方針は整理するが、画面・計算・DBの動作変更は含めない。

## 2. 文書体系の構成

### 全体を六つの柱で整理する

| 柱 | 本文で答える問い | 主な内容 |
|---|---|---|
| **① 投資の目的と自分自身** | 自分は何を目指し、どのような投資家でありたいか | 運用目的、資産形成、許容できない状態、自分の強み・弱み、心理、時間・資金・生活上の制約 |
| **② 市場と投資機会の捉え方** | どこに機会を見いだし、なぜ自分が取り組むのか | 市場評価と実態の差、情報の見つけ方、投資家の期待、業種・環境・需給、機会を待つ考え方 |
| **③ 企業と価値の理解** | その企業をどう理解し、何を基準に評価するか | 事業、競争、経営、業績、財務、資産、資金創出、資本政策、主評価・補助評価、比較方法 |
| **④ 投資判断の組み立て** | 今の情報と価格から、なぜ投資する・待つ・見送るのか | 仮説、因果、支持・反証、不明点、織り込み、条件別の上値・下値、時間軸、個別手法 |
| **⑤ 資金配分と保有中の判断** | どれだけ持ち、何を観測し、いつ判断を変えるか | サイズ、集中、流動性、レバレッジ、生存、追加・縮小・退出、入替、再エントリー |
| **⑥ 振り返りと考えの更新** | 経験から何を学び、現在の考えへどう戻すか | 判断と結果の分離、成功・失敗・見送り、心理と行動、成績評価、新しい手法、疑問、改訂理由 |

これは**読むための分類**とする。既存の戦略IDやアプリの分類は変更しない。利益モデルや決算分析は③・④の中に位置づけ、複合的な投資判断全体との関係を説明する。

### 四つの役割をつなぐ

| 役割 | 内容と使い方 |
|---|---|
| **入口** | 六つの柱、現在の投資思想の短い要約、目的別の読み順、未解決の問いへのリンク |
| **項目別の本文** | 現在の考えを説明する正本。具体的な理由や例外まで読む場所 |
| **事例・参考資料** | 実際の判断例、反例、計算例、一般理論、外部資料。本文の理解を助ける |
| **日々の記録と変更履歴** | 原発言、気づき、迷い、変更理由、過去の考え。本文の更新元として残す |

日々の記録は、生活観察や銘柄着想に加え、**自分の判断・心理・手法・運用への気づき**も扱う。全体目次には問いの所在を案内し、問いの説明自体は関係する本文に置く。

既存のフォルダと参照先を生かし、まず入口と内容の関係を組み替える。AIやアプリが参照するパスを一括移動せず、新規文書は既存の正本では独立した問いを収められない場合に限定する。

## 3. 項目別本文と日々の更新方法

### 本文の基本形

各項目は次の順序を基本にする。該当しない空欄は設けず、本人に読ませる文章として書く。

1. **この項目で考えること**：どんな疑問・場面で読むのか。
2. **現在の私の考え**：今どう捉え、どう判断しているか。
3. **そう考える理由**：背景、仕組み、経験、根拠。
4. **実際の使い方と例外**：適用例、反例、他の要因との関係。
5. **自分に問い直すこと**：見落としや思い込みを確かめる問い。
6. **まだ分からないこと**：未解決・検討中・確かめたい点。
7. **関連項目と変更の根拠**：詳細や元の対話へのリンク。

「現在の私の考え」は、実際の本人意思から記述する。AIの説明や参考理論から、本人の信念・経験・数値基準を補わない。本人が採用した考えでも、実証されていない部分はその限界を説明する。

### 日々の対話から本文へ戻す

**自由な発言・記録 → 関係する項目の特定 → 意思と問いの区別 → 本文への反映または提案 → 変更理由の保存**

- ユーザーは通常の言葉で話せばよく、分類や定型フォームへの入力を求めない。
- AIは関係する本文と既存の採用記録を読み、何が変わるのかを整理する。
- 明確な本人意思は、既存の承認範囲で関連本文まで反映する。同じ意味を再確認しない。
- 適用範囲が曖昧な発言や既存意思との衝突は、影響する解釈だけ確認する。
- 新しい手法への関心は、検討中の内容として残す。関心を示しただけで採用済みにしない。
- 個別の失敗からAIが一般ルールを導いた場合は提案とし、本人の意思とは分ける。
- 過去の判断は当時の資料・理由とともに保持する。現在の考えで再評価した結果は追加記録にする。

たとえば「利益成長を見すぎて、資金負担を軽く見ていた」という発言は、まず当該事例の気づきとして残す。「今後はこの種の企業では資金負担も重視する」という意思が明確なら、企業評価の本文へ適用範囲付きで反映する。

更新の手順は既存のレビュー・変更管理文書へ統合する。「月1件」「30取引・3か月」等は一般的な文書更新条件から外す。投資効果を検証する個別の手法や現行実装に残る制約は、用途と適用状態を説明する。

## 4. 既存文書からの移行とアプリへの接続

### 実施順序

1. **採用根拠を対応づける**  
   Q1〜Q127、後発訂正、今回の構成・更新方針を既存本文へ対応づける。Qwen側の別対話は出所を区別する。対応表は既存作業記録に置き、常設の新台帳にはしない。

2. **全体の入口と六つの柱を整える**  
   既存の[全体目次](D:/Dev/Investment/投資フレームワーク/00_INDEX/README.md)を改訂し、各項目の「何を考えるために読むか」を示す。自分自身や日々の内省など不足している内容には、確認済みの範囲を記述し、未言語化の部分を問いとして残す。

3. **採用済み内容で本文を改訂する**  
   思想、評価、判断、保有管理、振り返りまで横断して反映する。p*必須、解像度の確率化、PLを全投資の必須条件と読む説明など、既存合意と異なる記述を修正する。一般理論や旧仕様は位置づけを明示して保存する。

4. **日々の記録と本文更新を接続する**  
   既存の[R.9のレビュー手順](D:/Dev/Investment/投資フレームワーク/04_実行ルール/R.9_ログ_レビュー_改善手順.md)を改訂し、銘柄の成績だけでなく、本人の考えの変化を各本文へ戻せるようにする。原発言・重要な採否・実行記録は既存の記録先を使う。

5. **読みやすさと意味を確認し、正式統合する**  
   参照・構造・内容を確認し、既に合意した通常のGit・PR手順でmainへ統合する。未決事項は明示し、その全解決を文書整備の前提にしない。

### アプリとの関係

最初の文書整備では、公開API・DB・計算型の変更は行わない。固定パス・見出し・表を読む既存処理を確認し、読み取りに影響する変更は回避または後続対応として明示する。

後続のアプリ設計は、既存機能を使って次の三つの利用を支える。

- 項目ごとに現在の投資法を読み返す。
- 日々の気づきから、関連する本文・未解決の問いへ移る。
- 個別の投資判断を、当時の考え方と結びつけて振り返る。

文書の正式化とアプリでの利用可能性は分けて扱い、アプリ実装の完了条件にはこのPCの通常導線での実画面確認を含める。

## 5. 検証と完成条件

以下を代表的な対話・事例で確認する。投資成績の良さを、文書構成の完成条件にはしない。

- **読み返せる**：全体目次から、企業評価・待つ判断・サイズ・心理・振り返りなどの目的に応じた本文へ辿れる。
- **項目単独で理解できる**：現在の考え、その理由、適用範囲、例外、不明点が分かる。
- **AIが必要な範囲を扱える**：目次と関連リンクから必要な正本を特定でき、毎回全資料を読む必要がない。
- **合意を取りこぼさない**：採用済み事項に反映先または変更不要理由があり、後発訂正が優先されている。
- **発言を誤って一般化しない**：明言・迷い・新手法への関心・AI提案を適切に読み分けられる。
- **経験が本文へ戻る**：一つの気づきが複数の章に関係する場合も、重複する規則を増やさず必要な本文を更新できる。
- **過去を保持する**：新しい考えを採用しても、以前の判断理由と変更経緯を辿れる。
- **形式と参照が成立する**：対象のリンク、既存metadata、文書を読む処理への影響、必要な文書検査を確認する。

完成は、**現在の本人意思を説明する体系が通常の入口から読め、未解決の問いが見え、日々の気づきを本文へ反映する方法が一貫している状態**とする。本人の投資を完全に解明した状態は求めず、その時点の正式版として使いながら深めていく。
