# 荏原の初回決算分析を実Qwenで生成し、見本と課題を確認する

## 1. 今回の対象と記録

対象は、ユーザーが選択した**荏原製作所（6361）の2026年12月期2Q**。5セグメント、受注・受注残、利益増減要因、BS・CFを使い、合意した表示と原因説明を検証する。[公式説明資料](https://www.ebara.com/content/dam/ebara/grand-masters/entities/ja/pdf/ir/library/earnings/briefings-documents/2026/162_q2_presentation_jp.pdf)

以下の採用事項を、統合仕様・決定記録・既存worklogへ詳しく反映する。

- 重要な変化と相殺要因について、説明箇所・根拠・未説明部分を対応させる。
- 原因説明は、会社の説明、数値へ影響する仕組み、確認できた寄与、不明点までつなぐ。
- PL・BS・CFのつながりは、一つずつ根拠を確認する。同時に変化しただけで因果関係を確定しない。
- 最初は確認済みの数値・資料抜粋で分析品質を試し、その後に取得・抽出を含む検証へ進む。
- 新しい点数を作らず、誤り・重要な脱落・読みやすさを具体例で評価する。
- 現在の表を基準とし、生成結果を見てから追加改善を判断する。

当時の推奨理由、ユーザーの全採用回答、任天堂から対象を変更した経緯を区別して保存する。未回答の質問は文書へ追加しない。

## 2. 入力資料と計算を固定する

初回の情報時点は**2026年8月14日の決算開示一式**とする。短信・説明資料・同日関連開示を確認し、前年2Q・当年1Q・比較に必要な過去資料をそろえる。後日公開の説明スクリプトや質疑応答は、初回入力へ混ぜず、後着資料による更新用に分ける。

- 全ページの確認状況、原文、資料URL、ページ、対象期間、単位を保存する。
- 表の値・YoY・QonQ・利益率・構成比・増益寄与・予想進捗は、Qwenへ渡す前に決定論的に計算する。
- 単体2Qは累積2Qから1Qを差し引く。EPS・率・受注残は単純差分で作らず、それぞれの既決方法と比較条件を守る。
- 短信の百万円と説明資料の億円を区別し、丸められた数値から精度を作り足さない。
- 荏原のIFRS表示に合わせ、売上収益・税引前利益などの正式な項目名を使う。経常利益を独自に作らない。
- Con比は、発表前の同期間コンセンサスを確認できた場合だけ計算する。未取得をゼロや非開示に置き換えない。

数値とページを照合した後、**期待する説明と避けるべき断定を別ファイルに保存する**。この評価用の答えはQwenへ渡さない。計算モジュールの未接続部分を試験用計算で補う場合は、その範囲を明記する。

## 3. 実Qwenで生成する

固定された **Qwen3.8-27B・8K設定**で、既存のLLM Gatewayを経由して生成する。モデルの実体と応答モデルを確認し、別モデルへ自動代替しない。

- 既存処理の「主因は最大1件」「説明文の数字禁止」は今回の要求に合わないため、採用内容を反映した**試験専用の指示・出力形式**を用いる。製品側のプロンプトや保存契約は変更しない。
- 事業・セグメント、営業利益以下、BS・CF、受注・KPI・予想に分けて処理し、最後に全社評価へ統合する。
- 入出力が8Kに収まるよう分割する。資料・重要要因を黙って省略せず、各説明から原文と検証済み数値へ戻れるようにする。
- 表は検証済み計算結果から組み立て、原因説明はQwenに生成させる。寄与額の引用は許し、未開示額の推定や再計算はさせない。
- 起動が必要な場合は所有を記録した専用プロセスを使う。既存アプリ設定の恒久変更、他プロセスの停止、通知用workerの起動は行わない。
- 共有DBへの書込みは、許可された既存Gatewayの実行履歴に限定する。分析本文・企業データの登録は行わない。

初回の生出力を必ず保存する。問題を発見してもGPTが黙って書き換えず、修正・再生成した場合は別版として残す。

## 4. ユーザーへ返す見本と検証結果

チャット本文に、荏原の実数値と実Qwenの説明を使い、次の順で見本を掲載する。

**累積と予想進捗 → 単体 → セグメント累積・単体 → 受注 → KPI → CF → 資産・負債 → 原因説明・全社評価**

Con比の位置、前四半期の実数、利益率、構成比、短い出典、括弧付きの説明見出しを維持する。文章では表の変化率を反復せず、開示から分かる変動要因を説明する。

見本とは分けて、GPTの確認結果を示す。

| 確認事項 | 報告する内容 |
|---|---|
| 原因の正確さ | 会社説明の取り違え、根拠のない因果関係、期間混同 |
| 説明の網羅性 | 5セグメントの寄与・相殺、費用、金融損益・税金、資金への影響の脱落 |
| 開示の限界 | 資料に説明がない部分と、Qwenが見落とした部分の区別 |
| 表と本文 | 数値・単位・出典の整合、表の反復、重複説明 |
| 改善方法 | 入力不足、抽出、計算、指示、モデル解釈のどこを直すべきか |

入力・計算根拠・指示・生出力・モデル設定・所要時間・検証結果を一組で保存する。今回の完了は、**実生成した見本と、根拠を確認した問題点をユーザーが読める状態**。取得・抽出を含む全工程の検証と製品への接続は、今回の生成評価とは区別して残す。
