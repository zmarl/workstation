## 第 2 版の核心（本文の答えの骨子）

1. **「別の Linux サーバーへ移す」から「1 台 4 役の LLM ネイティブ投資ワークステーション」へ。** データ基盤・計算機・LLM/エージェント基盤・普段使いの机を 1 台で担い、資源の取り合いを **GPU 運転モード**（通常／大型モデル／学習／決算期）で統治する。
2. **「最初から全部」は「最初から全部を地図に載せ、条件を満たした部屋から解錠する」で実現する。** 初版が診断した失敗（横に増やして縦がつながらない、使われたか測らない）を繰り返さないため、機能は暦ではなく**解錠条件**（使われ方・評価セットの合格・データの準備）で増やす。フロアには未解錠の部屋も最初から見え、条件と進み具合が表示される。
3. **最初の一本は「決算スライス」**: 保有・監視銘柄の TDnet 決算 → 決定論の計算 → 決算アナリスト（27B）→ 検証器 → 企業ページと Discord → **オーナーのワンクリック評価**（役立った／違う＋理由）→ 評価セットへ還流。フロア v0 はこの 1 本だけを映す。1 月下旬〜2 月中旬の決算期を実際に処理できたら次の部屋を開ける。
4. **部品の大半が現 PC の流用なので 2 台並走はできない → 同一機での段階移行。** 新しい NVMe 4TB を 1 本だけ買い足し、旧 C:/D: は消さずに残す（Windows を起動できる退避路）。組み立てと Windows での動作確認を 11 月決算期の前に、Ubuntu への切替を決算期の後に置く。切替の隙間で TDnet（手元以外に残らない 31 日窓）を失わないよう、**OS に依存しない原本取得サービス**を 10 月に Windows 上で先に動かす。
5. **265F には内蔵 GPU がない。** 推奨は CPU を内蔵 GPU 付きの Core Ultra 7 265（無印）または 265K に替え、画面は内蔵 GPU、NVIDIA 2 枚は計算専用にする（デスクトップが固まっても LLM や DB を巻き込まない）。費用ゼロの代替は 5070 Ti に画面を出す案（利用中は学習・OCR を回さない規則付き）。
6. **「使えるものを全部使う」＝役割ごとに最適なエンジン、評価セットで入れ替え。** vLLM＝常駐の主力（Qwen3.8-27B FP8、まず内蔵 MTP で高速化）、llama.cpp＝2 GPU + メモリにまたがる大型モデルと過去分析との比較用プロファイル、SGLang＝比較用コンテナのみ、5070 Ti＝埋め込み・並べ替え・OCR・時系列基盤モデル。非対称 2 枚で GPU 間直結もないためテンソル並列は実用外。
7. **初版の安全構造は不変**（DB 権限で提案表にしか書けない、検証器、人の承認、LLM に算術をさせない、売買・順位・数量を出さない）。ゲーム要素は正しさにだけ報酬を与え、レベルは権限を一切与えない。
