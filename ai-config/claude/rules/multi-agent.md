# Subagent Usage Rules

原則として親が調査・実装・検証まで担当する。以下は独立して分離でき、時間短縮かリスク低減が見込める場合だけの選択肢。具体的な所有・レビュー条件はプロジェクトのAGENTS.mdに従う。

---

## When to Use Subagents

| ケース | 手法 |
|--------|------|
| 広範囲の調査（影響分析、パターン探索） | 探索サブエージェントを並列起動 |
| 独立した複数モジュールの同時変更 | モジュールごとにサブエージェント |
| 実装中の別領域リサーチ | バックグラウンドで調査サブエージェント |

## When NOT to Use Subagents

- 単一ファイルの修正、単純Q&A
- 密結合な変更（頻繁に共有状態を参照する作業）
- 調整コストが速度メリットを上回る場合

## Work Sequence

非自明な作業は以下の順序で進める。

1. **Discovery** — read-only でコードベースを調査（サブエージェント並列可）
2. **Plan** — 実装計画を策定。Plan Mode 利用を推奨
3. **Implement** — 計画に沿って実装
4. **Verify** — 変更影響に対応する lint + 対象 test を実行
5. **Retrospective** — 再発防止の知見があれば MEMORY に記録

## Failure handling

変更を否定できる最小の関連チェックから実行する。失敗原因を確認し、新しい証拠か修正がある場合だけ再実行する。同じ失敗を回数だけで反復せず、未承認の外部影響や所有外の境界があれば具体的な理由を報告する。

## Knowledge Capture

以下に該当すれば作業完了時に MEMORY.md またはサブファイルに知見を記録する。

- Auto Bug Fix が2回以上リトライした
- 既存パターンに反する実装が見つかった
- 新しい外部API/ライブラリの非自明な挙動を発見した
- 設計判断で重要な tradeoff があった

記録しない: 単純タイポ修正、一般的なプログラミング知識、一度きりの作業詳細。

## Peer Session Protection

- 他のCodex・Claude Code・terminalとその子プロセスは正常な並行作業である。lock/port解放、main clean化、gate、merge、cleanupを理由に停止・interrupt・terminal closeを実行・提案・依頼しない。
- 停止できるのは、現セッション自身が起動しPIDと開始時刻で所有を証明できる子プロセス、またはユーザーが対象を明示指定した場合だけとする。PID単独は所有証明にならない。
- 競合時は該当する同期・cleanupだけを延期し、`1 session = 1 task = 1 external worktree = 1 worklog`で独立作業を継続する。
- 外部トップレベルセッションは6並列を標準規模とし、ハード上限にしない。資源不足時も既存セッションを止めず、新規作業側だけを延期する。Codexの会話内subagent上限は現在の設定を参照し、外部セッション数と混同しない。
